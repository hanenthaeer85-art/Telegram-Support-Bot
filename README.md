# بوت وسيط رسائل تيليجرام

بوت Python يرسل رسائل المستخدمين الخاصة إلى حساب المشرف، ويعيد رد المشرف إلى المستخدم الصحيح عند استخدام Reply على الرسالة التي وصلت من البوت.

## الوظائف

- يرسل `/start` رسالة الترحيب: «أهلاً بك، أرسل رسالتك وسيتم إيصالها إلى الإدارة.»
- ينسخ الرسائل النصية والصور والأنواع الأخرى التي يدعم Telegram `copyMessage` نسخها إلى المشرف، مع بطاقة تعريف منفصلة.
- يمكن للمشرف الرد على بطاقة التعريف أو على نسخة الرسالة نفسها.
- تُحفظ علاقة رسائل المشرف بالمستخدمين ومعرّفات التحديث في SQLite، لتبقى بعد إعادة تشغيل العامل.
- يعيد المحاولة عند انقطاع الاتصال، ويسجل الأخطاء دون طباعة رمز البوت.

## الإعداد

أضف متغيري البيئة التاليين إلى إعدادات الاستضافة:

- `BOT_TOKEN`: رمز البوت من BotFather، واحفظه كسر.
- `ADMIN_ID`: معرّف Telegram الرقمي لحساب المشرف.

افتح البوت بحساب المشرف وأرسل `/start` مرة واحدة، ثم شغّل العامل. على المستخدمين إرسال `/start` إلى البوت قبل مراسلته.

للتشغيل المحلي:

```sh
python -m bot.main
```

## تشغيل مستمر على استضافة سحابية

هذا عامل طويل التشغيل يستخدم Telegram long polling ولا يحتاج إلى منفذ HTTP أو نطاق عام. أمر التشغيل موجود في `Procfile`:

```text
worker: python -m bot.main
```

أنشئ خدمة Worker/Background Worker لدى مزود الاستضافة، واستخدم الأمر `python -m bot.main` مع متغيري البيئة أعلاه. شغّل نسخة واحدة فقط من العامل حتى لا تتنافس عمليتا polling على البوت نفسه.

افتراضيًا تُحفظ قاعدة البيانات في `data/telegram-relay.sqlite3`. اربط هذا المسار بقرص تخزين دائم في الاستضافة، أو عيّن `BOT_DB_PATH` إلى مسار دائم مثل `/data/telegram-relay.sqlite3`. قاعدة SQLite المحلية لا تُعدّ تخزينًا دائمًا إذا كان مزود الاستضافة يحذف ملفات الخدمة عند إعادة النشر.

## ملاحظات التشغيل

- لا تضع `BOT_TOKEN` في الشفرة أو في مستودع Git.
- عند تغيير رمز البوت، حدّث السر في إعدادات الاستضافة وأعد تشغيل العامل.
- إذا تعذر على البوت مراسلة المشرف، تأكد أن حساب المشرف بدأ محادثة مع البوت وأن `ADMIN_ID` صحيح.
- إذا أرسل المشرف رسالة جديدة بدل Reply، فلن يستطيع البوت معرفة المستخدم المقصود؛ يجب الرد باستخدام Reply.
